# Gravemark (Undead Slayer-style pixel action RPG)

A 2D side-view pixel-art action RPG built with Phaser 3, Express 5 and SQLite. It has accounts,
saved progress, a 50-level campaign across 10 chapters with 10 bosses, a 10-hero roster with
gacha summons, equipment, upgrades, and a mobile-friendly battle HUD.

All art is procedurally generated by original code in `tools/art/` (no third-party sprites).

## Requirements

- Node.js 22.5 or newer (uses the built-in `node:sqlite` module)
- npm

## Setup

```bash
npm install
npm run assets     # optional: regenerate public/assets/ (committed, so usually not needed)
npm start          # http://localhost:3000  (listens on 0.0.0.0)
```

To use a `.env` file:

```bash
cp .env.example .env
node --env-file=.env server/index.js
```

Tests:

```bash
npm test           # node:test suite (rules, security, API flows, assets, battle AI)
```

## Configuration

| Variable | Default | Purpose |
| --- | --- | --- |
| `PORT` | `3000` | HTTP port |
| `HOST` | `0.0.0.0` | Bind address |
| `DATABASE_PATH` | `data/undead-slayer.db` | SQLite file (created on first start) |
| `COOKIE_SECURE` | `true` | Session cookies are `Secure; SameSite=None`. Set `false` only for plain-HTTP LAN testing |
| `SESSION_DAYS` | `14` | Session lifetime |
| `TRUST_PROXY` | `false` | Set `true` only behind a trusted reverse proxy |

```
  economy.js   summons, rewards, upgrades, inventory, battle completion
  progress.js  /api/* game routes

  scenes/      Phaser scenes (boot, menu, adventure, battle, results, and the menu pages)
  systems/     battle-core (pure combat AI and math), assets, audio

```

## Security

- Passwords are hashed with scrypt (N=16384, r=8, p=1, 16-byte salt) and compared with `timingSafeEqual`.
- Session tokens are random 32-byte values; only their SHA-256 hash is stored. Cookies are `HttpOnly`,
  `SameSite=None; Secure` over HTTPS (needed when the game runs inside an embedded preview, where browsers
  drop `SameSite=Lax` cookies) and `SameSite=Lax` over plain HTTP. Cookies last 14 days. Every state-changing
  route requires a JSON Content-Type, which cross-site forms cannot send.
- Login and recovery are rate-limited per IP and per username. Login failures return a generic
  "Invalid credentials" message.
- Registration validates usernames (3-20 chars, `A-Za-z0-9_`, case-insensitive unique), emails (unique,
  case-insensitive) and passwords (8-128 chars with a letter and a digit). JSON bodies are required on POST.
- Recovery codes are shown once after registration and stored hashed. "Forgot password" uses the recovery code
  (no email is sent). Changing the password or regenerating the code requires the current password.
- Rewards, unlocks, costs and summons are computed and enforced on the server.

## Gameplay and economy

- Gacha uses only earned in-game currency (coins or crystals). There is no real-money purchase and no
  paid randomness. Rates: Common 60%, Rare 30%, Epic 8%, Legendary 2%. Soft pity guarantees Epic+ after
  10 pulls without one; hard pity guarantees Legendary after 50. Duplicates convert to fragments.
- Single pull: 150 coins or 10 crystals. Ten pulls: 1350 coins or 90 crystals.
- Heroes unlock through coins, fragments, chapter clears, boss defeats or achievements (see each hero's unlock text).
- Hero upgrades (HP/ATK/DEF) cost coins plus Iron Ore; skills cost Rune Shards plus coins; ascension uses fragments.
- Potions have a limited supply, a cooldown, and never overheal. Boss chests drop equipment and materials.

## Battle controls

| Action | Keyboard | Touch |
| --- | --- | --- |
| Move | WASD / arrow keys | Left virtual joystick |
| Run | Shift | — |
| Attack (press up to 3× for a combo) | J | Attack button |
| Dodge (i-frames) | K or Space | Dodge button |
| Special (uses mana) | L | Special button |
| Potion (cooldown) | Q | Potion button |
| Pause / retreat | Esc or P | Pause button |

The team is the selected hero plus up to two AI companions, who respawn 15 seconds after falling.

## Known limitations (please read)

- **Combat runs in the browser.** The server validates rewards against the level definition (kill counts are
  capped by the level composition, potion use is checked, unlocks are checked), but it does not replay
  the fight. This is not anti-cheat-grade.
- Sprites are procedural and simple. Hero sprites read as silhouettes at 48px, and some rows have
  outline clipping. These are known art issues and not fixed.
- Verified so far: server API flows (57 automated tests), and in headless Chromium: the loader, account
  creation with the recovery code, every menu screen, a battle start and kill loop, and the results screen.
  Touch controls, audio, the full 50-level playthrough and the boss sprite rows have not been checked end to end.
